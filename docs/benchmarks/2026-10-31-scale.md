# Synthetic scale measurement

Measured with `uv run python -m tools.benchmark_scale --services 9 --files 3000
--symbols 10 --out report.json`, using the memory store and Python allocation
tracing. The generic Python/Java/Go fixture produced 35,028 nodes and 37,027
edges. [Raw measurements](2026-10-31-scale.json) include every phase.

| Run | Total | Publish | State | Files parsed |
| --- | ---: | ---: | ---: | ---: |
| Full | 25.85 s | 0.039 s | 4.75 s | 3,000 |
| Unchanged | 23.47 s | 0.010 s | 4.66 s | 0 |
| 1% source edit | 24.45 s | 0.009 s | 4.57 s | 334 |

Both subsequent runs used incremental state. The unchanged publication changed
only the repository generation marker; the edited publication changed 31 nodes
and no edges. Whole-service invalidation explains the 334 reparsed files after
30 source edits. Reconstruction and state work still dominate unchanged runs.

Peak process RSS was 857 MiB; traced Python allocation peak was 449 MiB. State
occupied 35.9 MiB and the largest compressed facts blob was 711 bytes. This is
a 3,000-file memory-store measurement, not acceptance evidence for 30,000 files,
live Neo4j, transaction caps, or a production memory/latency target. The nightly
workflow runs 30,000 files and records the same metrics, with configurable
6 GiB RSS and 64 MiB per-file blob ceilings.
