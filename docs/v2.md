# Axon v2 design

API-first code graph. Pure code parsing. Neo4j for persistence.

## Principles

- The unit of navigation is one API endpoint in one service. There is no
  whole-repo graph view; exploration starts from the API catalog and stays
  centred on one API and its bounded ego-graph.
- Answers are graph-grounded only. If the graph proves nothing, Axon says
  "unknown" — the language model never fills gaps from memory.
- Ownership comes from `axon.yaml`, never from a build graph. There is no
  Bazel query anywhere in the v2 path (the Bazel worker package is deleted).
- Every inferred edge carries confidence, the rule that produced it, and
  file:line evidence. Unresolvable outbound calls become `ExternalApi`
  placeholders plus an unresolved-links report — never silent drops.

## Graph model (`axon/v2/models.py`)

Nodes: `Repo`, `Service`, `SourceFile`, `Symbol`, `ApiEndpoint`, `ApiSpec`,
`ApiClient`, `ExternalApi`. Edges: `CONTAINS`, `DEFINES`, `EXPOSES`,
`HANDLES`, `CALLS`, `CALLS_API`, `GENERATED_FROM`, `IMPORTS`.

Endpoint identity is `repo + service + METHOD + normalized path`, so one
graph holds a monorepo and many small repos side by side. Endpoints found
in code and in OpenAPI specs are reconciled into one node (`source:
code|spec|both`).

Path templates are normalized across frameworks: Django `<int:id>`, Go
`:id`, and `{id}` all become `{id}`; matching compares template-insensitive
signatures.

## Service map (`axon.yaml`)

One file per imported repo, reviewed by PR. Services declare `roots`
(directories or globs, anywhere in a monorepo), `language`, `framework`,
`specs`, and `clients`. `shared:` marks libraries, `ignore:` excludes
paths, `links:` holds last-resort manual overrides. Unknown keys are
preserved. Longest matching root wins, so nested services work.

Disconnected generated clients (for example a swagger-generated client no
build file mentions) are resolved by a ladder in `axon/v2/linker.py`:
manual override → declared client target + operation name → declared base URL + method/path → method+path
template → operationId-style call name. The winning rule is stored on the
edge.

Two indirection patterns are seen through before that ladder runs.
Callable pass-through: when code passes a client method into a wrapper
that invokes its parameter (`call_payments_api(api.v1_list)` → retry helpers →
`fn()`), the indexer synthesizes the underlying call at the passing site
(rule `call-through`). Factory binding: source-visible returns from known client helpers (such as
`return get_V1Api(imported_sdk)`) and generated API constructors propagate client
package evidence through local/imported factories. Edges record
`factory:inferred-return`, the factory return location and the call site.
Dynamic package arguments remain diagnostic and unresolved. Django settings
imports resolve within the owning service using literal `DJANGO_SETTINGS_MODULE`
values in manage/wsgi/asgi files, or a unique settings file; ambiguous candidates
produce `django-settings:ambiguous`. Declared `factories:` remain the escape hatch
for factories whose implementation is absent, with `factory:declared` evidence.
Generated packages can be installed externally and absent from the source tree. When the generated
source is present, swagger-codegen `call_api("/path", "GET")` literals
inside its methods emit the operation directly. Factories without a declaration or source-visible return evidence stay
unresolved and reported. Module/class bindings and inherited generated-client
wrappers can resolve through their source metadata. Direct HTTP wrappers forward static strings and symbolic URL templates. Python
constructor arguments (including keyword/dictionary arguments), class attributes,
dataclass fields, properties, imported globals, and source-visible factory return
unions can supply client receiver evidence. Traversal has a depth limit of eight,
cycle guards, a constructor-site index and memoized top-level lookups. Annotated
factory returns take precedence. `client:<id>` edges carry a binding/type trace;
multiple supported clients use AMBIGUOUS `client:<id>(many-binding)` edges.

`base_urls` on a service or client accepts `env:REMOTE_URL`, `setting:API_URL`,
or a literal host. A client mapping scopes to its declared target; a service
mapping scopes to that service. Unmapped symbolic bases try concrete method/path
aliases, including specification base paths and known gateway prefixes. A unique
service match uses `path-fallback:<ref>` with AMBIGUOUS confidence. Exact matches
for one base become INFERRED only when their call sites agree on one service;
`(consistent:N)` records the number of source sites. Conflicts stay AMBIGUOUS
with a diagnostic; multiple candidate services remain external and reviewable.
Base references and source evidence remain attached. Opt-in
`index.path_suffix_fallback: true` permits an unknown prefix to match at least
three trailing segments with a concrete verb and unique target service; suffix
matches always remain AMBIGUOUS. `base-url:<ref>` records
the scoped match, including spec base-path aliases. Cross-service path collisions
stay ExternalApi with `unresolved:path-ambiguous`; `props.candidates` is a
JSON-encoded list of endpoint IDs (graph properties remain strings). Unresolved
absolute URLs retain their hosts, and symbolic URLs retain their base reference.
Queries and fragments are removed for matching. Unknown verbs use the ANY index;
template segments never match literal segments by broadening.

Python URL facts support concatenation, augmented assignment, f-strings, format
and percent templates, environment/settings bases, literal branch alternatives,
urljoin and client base URLs. Source-visible session assignments and context
managers are recognized. Constructor-injected URL attributes reuse bounded flow.

Callable hand-offs use `call:thread-target`, `call:executor`,
`call:celery-async`, and `call:callable-arg`. Source-visible factory dispatch uses
`dispatch:factory-return`; annotated base-class dispatch and literal-prefix
getattr candidates use AMBIGUOUS `dispatch:cha`, capped at 25 targets with
truncation diagnostics. Python constructors and known non-operation Java members
are diagnostics (`suppressed: non-operation client member`), rather than outbound
edges. Indexed API classes provide stronger operation-membership evidence.

Django/DRF source-visible lifecycle hooks live in `framework_hooks.py` and use
`framework:drf-implicit`. Hooks follow source-visible inheritance and configured
serializer, permission, filter and pagination classes. Generic API views and
ModelViewSet routes can use framework verb evidence even when the framework's
implementation is not indexed. Model save/delete calls with resolved sender
classes connect to declared signal receivers using AMBIGUOUS
`framework:django-signal`. Framework edges retain evidence in API graph responses
and render with dashed strokes even with animation paused.

Literal `packageName`/`apiPackage` values in `swagger.cfg`, and
`python_wheel_name`/`java_api_package` attributes in a `swagger_client` build
rule, can register generated packages for the service already owning that
metadata file. Build files are parsed as data and never executed; service
roots still come exclusively from `axon.yaml`. Conflicting package hints are
skipped and explicit client declarations win. Matching generated package
folders are marked as client source, so transport implementations do not
inflate service outbound coverage. Onboarding includes these hints in its
reviewable draft. Discovery does not rewrite an existing `axon.yaml`.

## Parsing (`axon/v2/parse_*.py`, `indexer.py`)

Two stages: per-file facts (symbols, calls, routes, outbound HTTP), then
graph assembly with name resolution. File collection prunes ignored
trees (`.venv`, `node_modules`, `.worktrees`, ...) instead of walking
them. Parsing is parallelized across processes on large repos
(`AXON_INDEX_WORKERS` to force a count, `1` for serial); name
resolution uses dotted-suffix indexes, so call linking stays linear in
calls + symbols rather than growing with their product.

Parsed facts are cached per file under
`~/.cache/axon/facts` (override with `AXON_FACTS_CACHE_DIR`, disable
with `AXON_FACTS_CACHE=0` or `axon index --no-cache`), keyed by file
bytes and parser version; re-indexing unchanged files skips parsing.
The cache is best-effort and can be deleted at any time. Per-phase
timings are available via `axon index --timings` and the `timings`
field of `POST /index`. The optional `index:` section of `axon.yaml`
controls file scope: `include_unowned` (default true) parses files
outside every service/shared root; `exclude_tests` (default true)
skips test-like paths (`test_*.py`, `*_test.go`, `*Test.java`,
`tests/` trees, `conftest.py`, ...) so test classes and functions
never become graph nodes unless explicitly opted in with
`exclude_tests: false`. The indexer logs how many collected files
are unowned and test-like on every run, and the repo node is stamped
with the scope options so changing them re-indexes instead of
hitting the already-indexed skip.

- Python (stdlib `ast`): symbols/calls; FastAPI decorators and
  `APIRouter(prefix=...)`; Django `path`/`re_path`/`url` including
  class-based views (`View.as_view()` links HANDLES from each verb
  method, and an `ANY` route attaches to same-path spec endpoints
  with concrete verbs) and `include()` mounts (inline lists and
  cross-file module mounts expand under their prefix); outbound
  `httpx`/`requests`, instance clients, and generated-client-style calls.
- Java (patterns): Spring `@RequestMapping`/`@GetMapping`/… with
  class-level prefixes; Vert.x `router.get/post/...handler(this::x)`;
  outbound RestTemplate, WebClient (`uri(...)`), Vert.x WebClient.
- Go (patterns): `func` symbols; `http.HandleFunc` including
  method-prefixed patterns (`"POST /orders"`); router-style
  `.GET/.POST(...)` registrations; outbound `http.Get/Post/NewRequest`.
- Flask: `route(..., methods=[...])` decorators, defaulting to GET.
- aiohttp: static router `add_get`/`add_post`/other verb registrations and
  `add_route(method, path, handler)`.
- JAX-RS: class/method `@Path` combined with HTTP verb annotations.
- Java Spring additionally accepts multiline generic return declarations,
  explicit mapping `path`/`value` attributes, and operation IDs from
  `@Operation` or `@ApiOperation`.
- OpenAPI/Swagger: reuses `axon/workers/swagger/parser.py`; spec base paths
  are preserved rather than silently discarded.

Overloaded declarations with the same qualified name share one symbol node. Its
span covers every declaration, and its `overloads` property records the count;
the signature is taken from the last declaration. The span can include unrelated
members between overloads.

Call resolution uses lexical scope, import aliases, package names, receiver
bindings, inheritance and source-visible factory returns. Dotted calls never
fall back to unrelated symbols sharing only a method name. Bare functions
prefer local/imported symbols, then unambiguous functions in the same service;
unimported functions in another service do not become call edges. Shared
libraries remain reachable through imports. Unique matches are EXTRACTED and
multiple supported candidates are AMBIGUOUS (capped). Primitive operations and
logging do not become unrelated domain calls. These are static evidence rules,
not runtime type resolution.

Parser behavior is pinned by per-language/framework evals in
`tests/evals/` (FastAPI, Django, Flask, aiohttp, Spring, JAX-RS, Vert.x,
Go, and a TypeScript known-gap case). They run in the default pytest and CI gates, and a new
parser language fails the build until it has eval coverage. See
[`evals.md`](evals.md).

Parse diagnostics: invalid escape sequences (for example `"\d"` regex
literals without the `r` prefix) and syntax errors in *target* code are
captured during parsing and reported as diagnostics, never printed raw
to stderr. They appear in the CLI index summary, in the `parse_warnings`
and `parse_warning_samples` fields of `POST /index`, and in the
snapshot's `diagnostics` list (not persisted to Neo4j). Other compile
warnings pass through unchanged.

### Known limitations

- Python files using syntax newer than the interpreter running Axon
  fail to parse; they produce empty facts and a syntax-error entry in
  diagnostics.
- Middleware is outside per-endpoint closure. Runtime registration, dynamically selected
  serializers/permissions, nested serializer internals without source-visible bindings,
  reflection, and configuration evaluated only at runtime can remain unknown.
- Dynamic route creation, framework extensions and settings evaluated only at
  runtime can still leave paths or handlers unknown. FastAPI imported router
  mounts transfer prefixes across files, including nested composition.
- Django function views without verb evidence remain `ANY` unless a matching
  spec supplies the method. Explicit DRF action maps and statically visible
  router registrations provide concrete verbs, including imported ViewSets and
  source-visible custom actions. Dynamically constructed routers can require
  more evidence. Flask Blueprint registration prefixes are not expanded.
- Index results carry per-service `coverage`: endpoint count, how many
  have a HANDLES handler, and outbound calls resolved to an indexed
  endpoint vs left as ExternalApi placeholders. The CLI index table
  prints the same counts, so a service whose handlers or clients are
  not linking is visible in the report instead of failing silently.
- Java/Go extraction is pattern-based, not fully type-aware. Java package,
  import, field, superclass and simple factory evidence improve call resolution;
  reflection, complex expressions and dynamic dispatch still produce ambiguous
  or missing edges by design.
- TypeScript services are not parsed by v2 yet (legacy TS worker remains
  on disk, unwired).

## Stores (`axon/v2/store.py`)

`AXON_STORE=memory|neo4j`. Memory serves tests, the CLI, and first-run
dev. Both stores publish a new in-memory snapshot pointer after a successful
save; existing readers retain their previous snapshot and traversal indexes.
Neo4j re-indexes compare graph rows and use an atomic delta when the change fits
one bounded batch. Larger replacements stage rows in separate bounded transactions,
then atomically switch repository publication markers to the complete generation.
Failed staging leaves the prior generation live. Obsolete rows are deleted by
label in bounded transactions after publication. Delta writes delete exact
evidence-bearing edge keys and write only changed rows. Legacy rows without
storage/delta keys trigger a full generation save.
Edge properties and full evidence survive database round trips. Both stores
report `last_save_s`; API index results expose it under `indexing.store_save_s`.

Physical storage IDs differ from public graph IDs. `axon-init` migrates the old
logical-ID uniqueness constraints to storage-ID constraints and logical lookup
indexes; old rows remain readable until their repository is rebuilt. Older
binaries must not share the migrated database. Hydration and model-drafted
Cypher filter nodes to published generations. Unsupported
Cypher forms fail closed rather than reading staged rows. Production Neo4j timing
and memory must be measured before claiming a rebuild budget. Constraints and
indexes are created by `axon-init`. Hydration streams records and caches the
snapshot, and warm-cache saves/deltas publish without rehydration. Snapshot JSON
files (`axon index --out`, `axon ask --snapshot`) keep CI database-free.

## HTTP API (`/api/v2`, `axon/v2/api.py`)

- `GET /repos`, `GET /services?repo=`, `GET /apis?service=&repo=&q=`
- `GET /apis/{id}` — first `handler` (compatibility), all `handlers`, outbound,
  callers, deprecatable flag
- `GET /apis/{id}/graph?depth=&max_symbols=&max_callers=&max_owners_per_caller=`
  — bounded ego-graph for one API. Defaults: 80 handler symbols, 50 callers,
  four owners per caller; caller band hard limit 80 nodes. Symbol limit is
  clamped to 1–500, callers to 0–80 and owners to 0–10. Outbound targets
  have a separate cap equal to the symbol limit. All handlers contribute to
  traversal. Shortest paths to outbound API calls are selected before shallow
  helpers; paths exceeding the budget are omitted whole. `truncated`,
  `total_symbols` and `total_callers` describe the partial result. Depth controls
  extra helper expansion; outbound paths can extend to the traversal limit of
  12 calls so visible API edges remain connected.
- `GET /functions?q=&repo=&used_in=&defined_in=&kind=&hide_handlers=true&unreached=false&sort=usage&limit=50&offset=0`
  — ranked function catalog with items, total and disjunctive facets (each facet
  applies all filters except its own). Repeat `used_in`, `defined_in` and `kind`
  for multiple selections. Used-in keys are `repo/service`; defined-in keys are
  `repo/kind/id`. Kinds are `function`, `method`, `class`. Sorts are `usage`,
  `apis`, `callers`, `name`; limit is bounded to 200.
- `GET /functions/apis?q=&repo=&used_in=&defined_in=` — compatible function-to-API
  lookup (up to 20 symbols), with additive owner and package metadata.
- `GET /functions/{symbol_id}` — shortest handler-to-function CALLS paths (at
  most 12 hops), edge evidence and weakest path confidence, plus direct callers.
- `GET /search?q=&limit=`
- `POST /ask {question, engine}` — answer + citations (+ Cypher when drafted);
  `engine` is `auto` (default), `deterministic`, or `model`
- `POST /index {repo_path}`, `POST /impact {repo_path, changed_files}`,
  `POST /onboard/scan {repo_path, write}`
- `POST /index/jobs {repo_path, commit, base_commit?}` (202, background index with progress),
  `GET /index/jobs/{id}`, `POST /index/jobs/{id}/cancel`; index jobs serialize by repository identity, with an additional
  repository-identity publication lock. New requests cancel older queued jobs
  for the same repository while leaving the running job to finish. Indexing an already-loaded commit is
  skipped (`already_indexed: true`) unless `force: true`; the commit
  defaults to the repo's git HEAD and is stamped on the repo node.
- `POST /onboard/scan/jobs` (202, background scan with file progress);
  generic `GET /jobs/{id}` and `POST /jobs/{id}/cancel` cover both job
  kinds (`kind: index | scan`).

The CLI is API-first: `axon init` and `axon index` run scan/index jobs
on the configured server (`axon configure --api-url`, else
`AXON_API_URL`, else `~/.axon/config.json`, else
`http://localhost:8080`) with live progress and ETA; `axon jobs watch`
reattaches to a detached job (Ctrl-C never cancels it). `--local`
(and `--out` / `--store neo4j` for `index`) keeps the in-process path.

`GET /api/v1/health` remains for probes. The v1 ops/graph/breaking
surfaces are unmounted (clean break).

## Ask (`axon/v2/ask.py`, `ask_entities.py`, `llm.py`)

Questions resolve services, endpoints and code-shaped symbols before routing.
Services match whole-token IDs or display names, including hyphen/underscore
variants; short names require a `service`/`svc` suffix or quoting. Equal aliases
are ambiguous. Endpoint paths require an exact path and, when needed, method or
service. Symbols require quoting, explicit function/method/class/symbol context,
or code shape (underscore, dotted name or internal capital). Bare English words
cannot accidentally bind code symbols. A lazy per-snapshot index serves lookups
and reverse handler ownership, invalidated on graph mutation.

Deterministic intents include service-to-service, service inbound/outbound,
endpoint callers/outbound, function-to-APIs, deprecation and catalog listings.
“Which APIs in scheduler call directory?” returns source/target endpoint rows
with caller file/line, resolution rule and graph confidence. Calls are direct
by default; `transitive` or `indirectly` explicitly follows intermediate APIs.
Reverse phrasing groups rows by the target endpoint. No resolved rows means only
that no call is proved in indexed code. Answers expose scoped unresolved calls,
missing handlers and client declaration gaps rather than claiming no calls exist.

`AskResponse` keeps `answer`/`citations` and adds `summary`, `rows`, `blind_spots`
and `bindings`. Bindings also appear in evidence. Row confidence retains the graph
model's enum strings (`EXTRACTED`, `INFERRED`, `AMBIGUOUS`, `MANUAL`), rather than
inventing numeric probabilities. Ambiguous or unmatched explicit entities return
clarification with `grounded=false`; Auto does not silently answer a different
question or fall through to a model in those cases.

`engine=auto` tries deterministic intents, then uses a configured model only when
no entities bind. `deterministic` never calls a model; `model` explicitly bypasses
deterministic routing. Resolved bindings are supplied as query hints. A model may
only draft read-only Cypher, validated before execution; answers use graph result
rows only. No model-memory synthesis or runtime telemetry is available.

Providers remain `none` (fully supported), `local` and `external`. The latter
use an OpenAI-compatible `/v1/chat/completions` endpoint configured through
`LLM_BASE_URL` and `LLM_MODEL`; unrecognized engines fall back to Auto.
RLCD is a training method, not a downloadable model. An offline contrastive
training loop remains optional future work, independent of runtime Ask.

Hand-authored Ask evals and an opt-in live audit are documented in `docs/evals.md`.

## PR impact (`axon/v2/impact.py`)

Changed files → symbols defined there (plus endpoints of changed specs) →
APIs whose handler closure contains them → reverse reachability over the
endpoint call graph. Output: affected APIs, services, repos, and a
Markdown PR comment. `.github/workflows/axon-impact.yml` runs this on
PRs here; `examples/github-actions/axon-impact.yml` is the copyable
version for target repos.

## Onboarding (`axon/v2/onboard.py` + skill)

`axon init --refresh` scans locally and prints a unified diff against the existing
effective map, preserving curation and overlays without overwriting any file.
Discovery collapses container folders and internal route/version packages;
independent nested services require their own build and bootstrap. Generic spec
titles use folder names, with parent names disambiguating collisions. Route-free
libraries are proposed as shared code. Doctor and refresh flag uncovered strong
anchors beneath shared roots; longest matching ownership roots win regardless
of kind. Symbolic URL mappings are suggestions with counts and source sites only.

`axon init` deterministically drafts `axon.yaml`, listing ambiguities
instead of guessing. Discovery is anchor-based so services at any depth
(under `services/`, elsewhere, or nested inside other services) are
found: validated OpenAPI/Swagger specs, app bootstraps, and framework
signal clusters each propose a service. A spec can sit anywhere inside
its service (`api/`, `src/main/resources/`, …); the root is inferred by
scoring the spec's ancestors for boundary markers (build files,
bootstraps, umbrella parents such as `services/`), with near-ties
reported for review. Duplicate and client/test spec copies never become
services, spec `info.title` drafts the service id/name, and the report
carries per-service `evidence`. File discovery uses `git ls-files` when
available and otherwise a pruned walk; `.worktrees/` and other
hidden/vendor trees are skipped (also in the indexer's default ignores).
`.agents/skills/axon-onboard/SKILL.md` defines the agent workflow:
scan, resolve ambiguities from evidence, declare clients, verify by
indexing. It also covers bring-your-own-config: translating an existing
service/resource registry in a format Axon does not parse (for example
a `code_registry` file the user names) into `axon.yaml`, cross-checked
against the scan. Humans merge the file by PR.

`axon init --ai` is the opt-in model pass (off by default, init-time
only). With an LLM configured (`LLM_PROVIDER`/`LLM_BASE_URL`/
`LLM_MODEL`, the same settings the ask endpoint uses), the model may
propose `target_service` and `spec` for drafted clients from the
scan's evidence. Suggestions are validated before they land: the
target must be a drafted service id and the spec must be a spec the
scan found, otherwise the suggestion is dropped and listed for
review. Applied suggestions are noted in the report with the model
name, and the draft header says AI-drafted fields require review.
The indexer never calls a model; the graph is built from the
committed `axon.yaml` alone.

## Web UI (`web/`)

React + Vite on design tokens, primitives, and components copied from Arc
into `web/base/` and `web/components/` (dark-first, colour = meaning, theme
switch including Colour mode). Pages: API catalog (the landing page),
Services, Service detail, API detail, Ask, Function→APIs, PR impact,
and Onboard.

There is deliberately no whole-graph overview: a full service map does
not scale to monorepos, so exploration starts from the API catalog and
stays per-API. The API detail page renders a pan/zoom request-flow canvas with card nodes,
elbow connectors, animated call packets, focus dimming, and a right-hand
node inspector. Ask is a dedicated page with structured cited answer rows and a centred
composer and engine picker. The empty state offers Skills and text prompts;
answers show a summary, source/target rows, blind spots and quiet metadata.
A single elapsed-time line appears while waiting. Citations navigate into the catalog. Without a backend
the main build shows an honest API-unreachable state and no graph data.
Direct links use `/repos/<repo-id>?service=<service-id>&api=<endpoint-id>`;
service/API values are query parameters and repository IDs are encoded path
segments. Repository-scoped catalogs filter the API request by repo. Other
pages use `view`, with optional `q` for Ask/Function; Back/Forward and refresh
restore the selected page. Static hosts must provide an SPA fallback for
`/repos/*`. See `web/README.md` for examples.

Demo is a separate build (`vite --mode demo`, via `npm run dev:demo` /
`build:demo`) that swaps the `@client` data source for a fixture dataset;
demo code and data are not part of the main build at all. See
`web/README.md` for the frontend layer rules.

## MCP (`axon-mcp/`)

A separately packaged stdio adapter proxies `/api/v2` through five tools:
`axon_search`, `axon_services`, `axon_api_graph`, `axon_function_apis`, and
`axon_ask`. It reads the API URL and optional bearer token from
`~/.axon/config.json`; `axon-mcp configure` writes that file and registers
the server in Claude Code's `~/.claude.json`. See `axon-mcp/README.md` for
client configuration and caching behavior.

## Legacy code still on disk

The v1 graph/ops/history modules and the Maven/pnpm/TS/Java/tree-sitter
workers remain in the tree but are not imported by the app, CLI, or
`pyproject` scripts. They are kept only as reference for a follow-up
physical purge. The default pytest and CI gates cover the active v2/CLI
implementation; legacy integration suites still need Neo4j (and some need a
running API) and are available by explicit path or through the manual
legacy CI jobs. The Bazel worker package and its dedicated tests are
deleted, although some orphaned legacy scenario tests still reference it.


## Resolution audit

`uv run python -m tests.evals.tools.resolution_audit snapshot.json --out audit.json`
buckets CALLS_API evidence rules, constructor/utility noise, unresolved requests,
and endpoints with no outbound edges. Source-file import evidence can flag likely
false negatives in the handler closure; old snapshots without that metadata cannot
prove their absence. Audit snapshots before and after a forced re-index, compare
`IndexTimings.call_through_s` and `link_http_s`, and inspect newly inferred edges.
The audit accepts any saved snapshot and contains no target-repository names.

## Configuration overlays and setup verification

`axon.yaml` can load `extends: base.yaml` (or a list of base files), then
apply its own fields and `overrides: axon.overrides.yaml` (a path, list of
paths, or inline mapping). Paths resolve relative to the file containing
them. Cycles and missing files fail. Services merge by `id`, and their
clients merge by `id`; other lists replace their previous value. Append
explicitly with, for example, `ignore: {+append: ["**/migrations/**"]}`.
A field omitted from an overlay retains its inherited value.

```yaml
extends: axon.generated.yaml
overrides: axon.overrides.yaml
```

`axon doctor --repo .` checks roots, shared overlaps, declared/discovered
specs and their owners, client targets, and unused client packages. Unused
packages are warnings because static imports and BUILD declarations cannot
prove dynamic usage. Suggested ignores are advisory. Nothing is executed
from the target repository.

`axon verify --repo . --golden axon.golden.yaml` indexes locally and checks
reviewed expected and forbidden outbound targets. Use `--snapshot graph.json`
to verify a saved snapshot instead. A failing case exits nonzero. Evidence
file/line constraints pin the call site, and the command prints source snippets.

```yaml
version: 1
cases:
  - id: reviewed-call
    api: {service: app, method: GET, path: /local}
    expect:
      - service: remote
        method: GET
        path: /items
        evidence: {file: app/views.py, line: 12}
    forbid:
      - service: unrelated
```

The example is a schema illustration; replace its names and evidence with
reviewed source before use. The committed [registry generator pattern](../examples/registry-onboarding/REGENERATE.md)
shows how to retain the generator, pinned inputs, prompt, manual overrides,
and verification runbook together. Registry schema adapters remain local to
the repository being onboarded; the example never imports registry code.

Index provenance includes the commit, `dirty: true|false|unknown`, and a SHA-256
fingerprint covering every loaded configuration file. Dirty or unknown working
trees, changed configuration bytes, and changed scope options prevent an
already-indexed skip. Commits label the checkout; supplying a commit does not
check it out. Per-service `resolution` reports include handler percentage,
zero-endpoint warnings and unresolved-rule buckets. Zero endpoints are a
review signal, not proof that a service must expose an HTTP API.

Python module aliases and imported binding/constants prefer the calling
service, then declared shared libraries, then unowned code. A different
service root cannot supply a fallback symbol. HTTP transports never use the
global operation-name rung. That rung requires a distinctive multi-token
operation name after removing generated sibling suffixes. Declared client
scopes can match single-word operations; multiple operation matches remain
ExternalApi placeholders with `unresolved:operation-ambiguous` and candidate IDs.
Inherited DRF actions point at source-visible base methods with rule
`framework:drf-implicit(inherited)`. Otherwise HANDLES points at the real class
with `implicit_action` and `inherited_from`; no nonexistent method is created.
API detail shows the implied action and base, using dashed framework edges.
Route file/line remains separate. Nested serializers receive validation/representation
hooks, while only root serializers receive create/update. Source-visible
`get_serializer_class` returns supersede `serializer_class`; dynamic selection
is reported as unknown.


## Incremental state and audit

Startup store loading runs off the event loop. `/health` reports `warming` and
progress, and CLI polling retries transient transport failures with backoff.
Job records persist at `$AXON_STATE_DIR/jobs.db`; unfinished jobs become
`interrupted` on restart. Assembly, `publish` and `state` precede `done`.

API index jobs persist SQLite state at `$AXON_STATE_DIR/<repo>/state.db`
(default `~/.axon/state`). State includes raw parser facts, separate synthesized
facts, file/interface hashes, conservative ownership scopes and lookup keys,
outbound link keys, graph identifiers, parser/config fingerprints, commit and
generation. Schema version 2 compresses each file independently and normalizes
node/edge ownership, without serializing the full graph. Loading reconstructs
graph rows from the published store and checks its generation against the state
marker. Older schemas are cache misses. A temporary SQLite file is renamed into
place after graph publication. State persistence failure finishes the job with
an `incremental state not saved` warning and forces a later rebuild. Corrupt,
missing or unwritable state causes a full rebuild on the next update. Results
report `indexing.mode`, `fallback_reason`, dirty/reused file counts, delta row
counts, and persistence timing.

Clean, matching Git revisions use a NUL-delimited rename-aware diff. Changed
services are re-resolved, unaffected service facts and call edges are reused,
and **all outbound facts are re-linked** against the complete new endpoint set.
This includes unchanged callers when a new endpoint introduces ambiguity.
Symbols, routes and specifications are assembled into a fresh snapshot; only the
delta is published. Checkout HEAD and configuration are checked before publication.
An optional `axon.golden.yaml` is checked before every publication; failures keep
the previous graph and state available.

Invalidation is intentionally conservative: an entire affected service is dirty.
Repositories containing shared, unowned or generated-client source use full
resolution because cross-owner receiver inference is not yet tracked precisely.
Changed configuration/parser/build fingerprints, metadata/spec/BUILD changes, graph-unsound diagnostics,
more than 15% changed files, an unavailable diff, dirty/unknown checkout or a
mismatched stored generation also fall back. This is not yet the fine-grained
resolver dependency and link-key scheduling described in the longer roadmap.
There is no asserted two-minute or five-minute latency guarantee. Background
jobs continue serving the prior snapshot until publication.

`axon verify-index --repo . --snapshot graph.json` (or the configured persistent
store) performs a read-only shadow full rebuild and compares
it with persisted state at the same clean commit. Differences exit nonzero; it
never replaces the served graph. Generic body/symbol/file/endpoint/spec/build
edit regressions and an update across every eval fixture compare incremental
results with full rebuilds. `examples/hooks/axon-post-merge` submits an index job;
`examples/github-actions/axon-index-audit.yml` shows a nightly audit on the host
owning the checkout/state. These are examples to install, not active schedules.

Generated-client discovery has a bounded process-local cache keyed by effective
configuration, metadata bytes and the file manifest. File collection uses Git's
tracked/untracked inventory, falling back to a pruned walk. Resolver parallelism
remains future performance work.

`axon verify-sample --repo . --services N --apis M --seed S --out review.json`
selects APIs with cross-service calls and emits source snippets, shortest symbol
chains, target locations and edge evidence. Range flags identify suspicious
handler/call locations. A route-to-handler gap containing only annotations,
blank lines, and supported Java-style comments is exempt from the gap flag;
unreadable or out-of-repository source remains flagged. Set row verdicts to `ok`, `wrong-handler`, `false-edge`
or `missing-edge`, then rerun with `--review review.json --export-golden
axon.golden.yaml`; only confirmed `ok` rows become expectations. Saved snapshots
are supported via `--snapshot`. This is a review tool, not an accuracy score.

`tools.benchmark_scale` generates generic multi-language repositories and measures
full/unchanged/1%-edited indexing, including phase times, peak memory and state
size. The scheduled workflow uploads reports. Live Neo4j generation visibility
and low-transaction-cap acceptance require a running development database.


## Route and link accuracy

DRF routers mount through `include(router.urls)` and URL-list assignment,
augmentation, concatenation, spread, `extend` and `append`, including aliases
and parent URL modules. Router registrations and custom actions retain their
prefixes; the generated DefaultRouter root is excluded.

Java Spring and JAX-RS annotation paths fold string concatenation and class,
outer-class, interface and indexed imported constants. Path arrays expand to
separate endpoints. Unresolved operands produce `{unresolved}` and
`route-path-partial` diagnostics rather than silently retaining only the first
literal. Partial routes are excluded from inferred path matching.

Existing braced parameters and custom-verb suffixes are opaque during path
normalization. Call-side symbolic parameters become `{var}` after removing the
leading base reference; original URLs remain on edges. Endpoints expose
`literal_segments` and `catch_all` as string properties. Catch-all and
parameter-only routes remain navigable and reachable through manual links and
operation IDs, but cannot enter method/path, gateway suffix or fallback indexes.
Fully dynamic HTTP paths use `unresolved:dynamic-path` with no path candidates.

Exact literal routes take precedence. A concrete call segment can fill one
endpoint parameter only when at least two other literal segments agree, there
is exactly one substitution, the concrete verbs agree, and candidates belong
to one service. `match:literal-param` stays AMBIGUOUS and stores JSON `bound`
parameter evidence. Independent exact base agreement can promote it.

Two distinct exact call sites agreeing on one service can resolve a path tie
when exactly one candidate belongs to that service. Such edges retain all
JSON `candidates`, use `path-fallback:<ref>(consensus:N)`, and remain AMBIGUOUS.
Declared base mappings win. Votes are scoped to the caller repository/service;
`self`/`cls` attributes additionally require the same file and class, and local
attribute receivers require the same caller. Unrelated objects sharing a field
name cannot vote for each other. `axon doctor` suggests reviewable `base_urls`
entries; it never writes configuration.

Generated operation names accept snake_case and Java camelCase HTTP-info,
streaming and async suffixes. Indexed generated method transport paths provide
identity through the CALLS traversal and declared client scope. Numeric `_N`
suffixes without source are considered only for duplicate operation IDs in the
target spec. Those alternatives remain ExternalApi candidates with AMBIGUOUS
`client:<id>(dedupe-suffix)` evidence; no arbitrary duplicate is selected.

## Generated source and external dependencies

Declared clients with empty `paths` are located across the repository using
package path segments plus a codegen banner or ApiClient sibling. Enrichment is
in memory only; doctor suggests explicit `paths`. Client source is traversable
but excluded from service outbound coverage. Transport internals and operation
guesses inside generated source are suppressed; concrete HTTP facts remain.
Java native/java.net.http, okhttp, RestTemplate and Feign generated templates
emit `generated-source` facts with method-local path/verb evidence. Placeholder
replacement chains preserve subsequent concatenation. Unsupported dynamic path
construction is diagnosed rather than truncated.

Generated model types, source-visible return types and factory return bindings
prevent model/response accessors from becoming operations. Fallback bean,
builder and Object accessors are suppressed only when no matching target
operation exists. Source-visible factory calls bind their return type. Real
zero-argument operations listed in the spec remain eligible.

Receiver names alone never establish a generated client. Declared/discovered
packages, factory bindings and import/type evidence establish client identity.
Untyped receiver counts are diagnostic coverage signals. Concrete HTTP verbs
with URL-shaped literals still supply transport evidence. HTTP URL validation
rejects whitespace, SQL and non-URL resource strings before node creation;
bare symbolic environment values alone do not prove HTTP.

The import/constructor-based SDK catalog retains cloud, metrics, messaging,
cache, search and database operations as ExternalApi nodes with `kind=sdk` and
`provider`. These use `external:sdk` evidence and appear as
`external_dependencies` in coverage, separately from unresolved inter-service
links. No SDK arguments are interpreted as HTTP paths.

## Cache compatibility and diagnostics

Parser cache keys use normalized Python AST fingerprints of each language
parser and its shared extraction helpers, plus manual override epochs. The
AST serialization is independent of Python's `ast.dump` formatting and omits
empty fields added by newer Python versions, so the same implementation has
the same fingerprints across supported Python versions. Populated fields,
including type parameters, remain part of the fingerprint. The
indexer fingerprint covers parsing, linking, synthesis, discovery and graph
assembly dependencies. State fingerprints cover DDL/serialization and the
schema version. Comments and formatting alone do not invalidate cache keys.
`tests/v2/build_fingerprints.json` is an explicit review gate: update its
parser/indexer/state values whenever an implementation fingerprint changes.

Repo nodes stamp `axon_build`. A same-commit request skips indexing only when
that build matches. Saved incremental state includes indexer, parser and state
fingerprints; upgrades force one full rebuild (`indexer-changed`) rather than
reusing old resolved facts. The CLI reports the upgrade when the job completes.

Per-file parser diagnostics persist with FileState facts and carry a severity:
`informational` warnings never prevent incremental work; `file-degraded` files
are retried on every run, bypassing cached degraded facts; `graph-unsound`
truncation of cross-file synthesis forces a full rebuild. Repository markers
preserve degraded/unsound status even when the displayed diagnostic list is
capped. Same-commit skips are disabled for degraded or unsound graphs. Dirty
checkout indexing remains conservative; working-tree incremental indexing is
not introduced by this change.


## Function reach and ownership

The Functions → APIs catalog measures **static reach**, never traffic or runtime
usage. APIs reached are endpoints whose handler CALLS closure includes a symbol
at depth ≤ 12 (including the handler at depth zero). Services reached count
unique `(repo, service)` pairs. Direct callers count distinct incoming CALLS
symbols, including those outside API closures. Cross-service means reach from
at least two such service pairs. The default ranking is services, APIs, callers
(descending), then function name and ID; handler symbols are hidden by default.
Used-in filters restrict endpoint counts and ranking to selected services.

A lazy snapshot usage index traverses each distinct handler once, retaining
endpoint membership and minimum depth per symbol without filling the general
closure cache. Build time and entry count are logged. Graph mutations invalidate
the index. Existing `endpoint_of_symbol`, Ask and impact semantics are unchanged.
No production latency budget is claimed without measuring the deployment graph.

`owner_root` on Symbol nodes records the matching `axon.yaml` service/shared/client
root (longest match wins). Older snapshots fall back to the first path segment
for shared/unowned labels until reindexing; the indexer fingerprint forces fresh
assembly on the next index. Package labels derive from language and source path,
not a runtime package registry. Unowned is an ownership classification, not a
claim that the symbol is unused.

“Not reached by any indexed API” means zero known API closures. Workers, CLIs,
jobs, reflection and framework hooks may be outside static analysis; these
symbols are never classified as dead code. Call-path confidence is the weakest
edge on the chosen shortest path; the inspector retains each edge's rule and
file/line evidence so ambiguous reach remains reviewable.

Newly indexed Repo nodes also retain `source_path` (the absolute indexing root).
Function details expose it for local editor definition links. Older snapshots
without it offer a copyable relative file/line location until reindexed. Remote
server source paths describe that server's checkout and require a matching local
checkout for editor navigation.
