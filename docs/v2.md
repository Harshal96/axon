# Axon v2 design

API-first code graph. Pure code parsing. Neo4j for persistence.

## Principles

- The unit of navigation is one API endpoint in one service. There is no
  whole-repo graph view; exploration starts from the API catalog and stays
  centred on one API and its bounded ego-graph.
- Answers are graph-grounded only. If the graph proves nothing, Axon says
  "unknown" — the language model never fills gaps from memory.
- Ownership comes from `axon.yaml`, never from a build graph. There is no
  Bazel query anywhere in the v2 path (the Bazel worker package is deleted).
- Every inferred edge carries confidence, the rule that produced it, and
  file:line evidence. Unresolvable outbound calls become `ExternalApi`
  placeholders plus an unresolved-links report — never silent drops.

## Graph model (`axon/v2/models.py`)

Nodes: `Repo`, `Service`, `SourceFile`, `Symbol`, `ApiEndpoint`, `ApiSpec`,
`ApiClient`, `ExternalApi`. Edges: `CONTAINS`, `DEFINES`, `EXPOSES`,
`HANDLES`, `CALLS`, `CALLS_API`, `GENERATED_FROM`, `IMPORTS`.

Endpoint identity is `repo + service + METHOD + normalized path`, so one
graph holds a monorepo and many small repos side by side. Endpoints found
in code and in OpenAPI specs are reconciled into one node (`source:
code|spec|both`).

Path templates are normalized across frameworks: Django `<int:id>`, Go
`:id`, and `{id}` all become `{id}`; matching compares template-insensitive
signatures.

## Service map (`axon.yaml`)

One file per imported repo, reviewed by PR. Services declare `roots`
(directories or globs, anywhere in a monorepo), `language`, `framework`,
`specs`, and `clients`. `shared:` marks libraries, `ignore:` excludes
paths, `links:` holds last-resort manual overrides. Unknown keys are
preserved. Longest matching root wins, so nested services work.

Disconnected generated clients (for example a swagger-generated client no
build file mentions) are resolved by a ladder in `axon/v2/linker.py`:
manual override → declared client target + operation name → method+path
template → operationId-style call name. The winning rule is stored on the
edge.

Two indirection patterns are seen through before that ladder runs.
Callable pass-through: when code passes a client method into a wrapper
that invokes its parameter (`call_payments_api(api.v1_list)` → retry helpers →
`fn()`), the indexer synthesizes the underlying call at the passing site
(rule `call-through`). Factory binding: if consumers obtain the client
from a settings factory, declare it on the client
(`factories: [settings.GET_PAYMENTS_API]`); receivers assigned from that
factory resolve under the client's packages even when the generated
package is pip-installed and absent from the repo. When the generated
source is present, swagger-codegen `call_api("/path", "GET")` literals
inside its methods emit the operation directly. Undeclared factories
stay unresolved and reported; nothing is guessed.

## Parsing (`axon/v2/parse_*.py`, `indexer.py`)

Two stages: per-file facts (symbols, calls, routes, outbound HTTP), then
graph assembly with name resolution. File collection prunes ignored
trees (`.venv`, `node_modules`, `.worktrees`, ...) instead of walking
them. Parsing is parallelized across processes on large repos
(`AXON_INDEX_WORKERS` to force a count, `1` for serial); name
resolution uses dotted-suffix indexes, so call linking stays linear in
calls + symbols rather than growing with their product.

Parsed facts are cached per file under
`~/.cache/axon/facts` (override with `AXON_FACTS_CACHE_DIR`, disable
with `AXON_FACTS_CACHE=0` or `axon index --no-cache`), keyed by file
bytes and parser version; re-indexing unchanged files skips parsing.
The cache is best-effort and can be deleted at any time. Per-phase
timings are available via `axon index --timings` and the `timings`
field of `POST /index`. The optional `index:` section of `axon.yaml`
controls file scope: `include_unowned` (default true) parses files
outside every service/shared root; `exclude_tests` (default true)
skips test-like paths (`test_*.py`, `*_test.go`, `*Test.java`,
`tests/` trees, `conftest.py`, ...) so test classes and functions
never become graph nodes unless explicitly opted in with
`exclude_tests: false`. The indexer logs how many collected files
are unowned and test-like on every run, and the repo node is stamped
with the scope options so changing them re-indexes instead of
hitting the already-indexed skip.

- Python (stdlib `ast`): symbols/calls; FastAPI decorators and
  `APIRouter(prefix=...)`; Django `path`/`re_path`/`url` including
  class-based views (`View.as_view()` links HANDLES from each verb
  method, and an `ANY` route attaches to same-path spec endpoints
  with concrete verbs) and `include()` mounts (inline lists and
  cross-file module mounts expand under their prefix); outbound
  `httpx`/`requests`, instance clients, and generated-client-style calls.
- Java (patterns): Spring `@RequestMapping`/`@GetMapping`/… with
  class-level prefixes; Vert.x `router.get/post/...handler(this::x)`;
  outbound RestTemplate, WebClient (`uri(...)`), Vert.x WebClient.
- Go (patterns): `func` symbols; `http.HandleFunc` including
  method-prefixed patterns (`"POST /orders"`); router-style
  `.GET/.POST(...)` registrations; outbound `http.Get/Post/NewRequest`.
- OpenAPI/Swagger: reuses `axon/workers/swagger/parser.py`.

Call resolution is name-based with confidence: unique match = EXTRACTED,
multiple candidates = AMBIGUOUS (capped). Client-looking receivers prefer
client-owned symbols over like-named API handlers.

Parser behavior is pinned by per-language/framework evals in
`tests/evals/` (FastAPI, Django, Spring, Vert.x, Go, and a TypeScript
known-gap case). They run in the default pytest and CI gates, and a new
parser language fails the build until it has eval coverage. See
[`evals.md`](evals.md).

Parse diagnostics: invalid escape sequences (for example `"\d"` regex
literals without the `r` prefix) and syntax errors in *target* code are
captured during parsing and reported as diagnostics, never printed raw
to stderr. They appear in the CLI index summary, in the `parse_warnings`
and `parse_warning_samples` fields of `POST /index`, and in the
snapshot's `diagnostics` list (not persisted to Neo4j). Other compile
warnings pass through unchanged.

### Known limitations

- Python files using syntax newer than the interpreter running Axon
  fail to parse; they produce empty facts and a syntax-error entry in
  diagnostics.
- FastAPI `include_router` prefixes applied in a *different* file than the
  routes are not yet transferred; declare `APIRouter(prefix=...)` or fix
  the path with a `links:` override.
- Django endpoints are method-agnostic (`ANY`) unless a spec endpoint
  with the same path supplies the verb. DRF router-registered
  viewsets without explicit `path()` entries are not extracted yet.
- Index results carry per-service `coverage`: endpoint count, how many
  have a HANDLES handler, and outbound calls resolved to an indexed
  endpoint vs left as ExternalApi placeholders. The CLI index table
  prints the same counts, so a service whose handlers or clients are
  not linking is visible in the report instead of failing silently.
- Java/Go extraction is pattern-based, not type-aware. Reflection and
  dynamic dispatch produce ambiguous or missing edges by design.
- TypeScript services are not parsed by v2 yet (legacy TS worker remains
  on disk, unwired).

## Stores (`axon/v2/store.py`)

`AXON_STORE=memory|neo4j`. Memory serves tests, the CLI, and first-run
dev. `Neo4jStore` persists snapshots with batched `UNWIND` MERGE writes
in managed (retrying) transactions, deletes replaced repos in
`IN TRANSACTIONS` sub-batches, and hydrates snapshots for queries by
streaming records into a per-instance cache (single-flight; saves
merge into the cache instead of forcing a rehydration). The server
prewarms that cache in the background at startup, and synchronous API
handlers run in FastAPI's threadpool, so a cold hydration never blocks
the event loop or health checks. It creates v2 constraints/indexes
(`axon-init`) and executes validated read-only Cypher. Snapshot JSON files
(`axon index --out`, `axon ask --snapshot`) make CI runs database-free.

## HTTP API (`/api/v2`, `axon/v2/api.py`)

- `GET /repos`, `GET /services?repo=`, `GET /apis?service=&repo=&q=`
- `GET /apis/{id}` — handler, outbound, callers, deprecatable flag
- `GET /apis/{id}/graph?depth=` — bounded ego-graph for one API
- `GET /functions/apis?q=` — APIs a function is part of
- `GET /search?q=&limit=`
- `POST /ask {question, engine}` — answer + citations (+ Cypher when drafted);
  `engine` is `auto` (default), `deterministic`, or `model`
- `POST /index {repo_path}`, `POST /impact {repo_path, changed_files}`,
  `POST /onboard/scan {repo_path, write}`
- `POST /index/jobs` (202, background index with progress),
  `GET /index/jobs/{id}`, `POST /index/jobs/{id}/cancel`; one job runs
  at a time per server process. Indexing an already-loaded commit is
  skipped (`already_indexed: true`) unless `force: true`; the commit
  defaults to the repo's git HEAD and is stamped on the repo node.
- `POST /onboard/scan/jobs` (202, background scan with file progress);
  generic `GET /jobs/{id}` and `POST /jobs/{id}/cancel` cover both job
  kinds (`kind: index | scan`).

The CLI is API-first: `axon init` and `axon index` run scan/index jobs
on the configured server (`axon configure --api-url`, else
`AXON_API_URL`, else `~/.axon/config.json`, else
`http://localhost:8080`) with live progress and ETA; `axon jobs watch`
reattaches to a detached job (Ctrl-C never cancels it). `--local`
(and `--out` / `--store neo4j` for `index`) keeps the in-process path.

`GET /api/v1/health` remains for probes. The v1 ops/graph/breaking
surfaces are unmounted (clean break).

## Ask (`axon/v2/ask.py`, `llm.py`)

The `auto` engine uses deterministic intents first: deprecation check,
outbound APIs/services, callers, function→APIs, list services/APIs.
Deprecation wording is honest: "no callers in indexed code" plus the
static-analysis blind spot, never an absolute "safe to delete". The
`deterministic` engine stops there and never consults a model. The
`model` engine skips the deterministic layer.

Open questions in `auto` or `model` mode use the configured model only to
draft one read-only Cypher query. `validate_readonly_cypher` rejects writes
and multi-statements. The query runs on Neo4j and the answer is rendered
from result rows. Unrecognized engine values fall back to `auto`.

Providers: `none` (fully supported), `local`, `external` — the latter two
call an OpenAI-compatible `/v1/chat/completions` endpoint at
`LLM_BASE_URL` with `LLM_MODEL` (any Hugging Face model id served locally,
for example via `vllm serve`, or any external URL). Hugging Face's own
Text Generation Inference is maintenance-mode upstream, so Axon does not
depend on it; any compatible server works by config alone.

On "RLCD": RLCD (Reinforcement Learning from Contrastive Distillation) is
a training method, not a downloadable model. Runtime therefore uses a
configurable model as above. An RLCD-style tuning loop — contrastive
pairs of grounded vs ungrounded answers verified by query execution,
preference model, then RL — is planned as an optional offline phase and
is not required at runtime.

## PR impact (`axon/v2/impact.py`)

Changed files → symbols defined there (plus endpoints of changed specs) →
APIs whose handler closure contains them → reverse reachability over the
endpoint call graph. Output: affected APIs, services, repos, and a
Markdown PR comment. `.github/workflows/axon-impact.yml` runs this on
PRs here; `examples/github-actions/axon-impact.yml` is the copyable
version for target repos.

## Onboarding (`axon/v2/onboard.py` + skill)

`axon init` deterministically drafts `axon.yaml`, listing ambiguities
instead of guessing. Discovery is anchor-based so services at any depth
(under `services/`, elsewhere, or nested inside other services) are
found: validated OpenAPI/Swagger specs, app bootstraps, and framework
signal clusters each propose a service. A spec can sit anywhere inside
its service (`api/`, `src/main/resources/`, …); the root is inferred by
scoring the spec's ancestors for boundary markers (build files,
bootstraps, umbrella parents such as `services/`), with near-ties
reported for review. Duplicate and client/test spec copies never become
services, spec `info.title` drafts the service id/name, and the report
carries per-service `evidence`. File discovery uses `git ls-files` when
available and otherwise a pruned walk; `.worktrees/` and other
hidden/vendor trees are skipped (also in the indexer's default ignores).
`.agents/skills/axon-onboard/SKILL.md` defines the agent workflow:
scan, resolve ambiguities from evidence, declare clients, verify by
indexing. It also covers bring-your-own-config: translating an existing
service/resource registry in a format Axon does not parse (for example
a `code_registry` file the user names) into `axon.yaml`, cross-checked
against the scan. Humans merge the file by PR.

`axon init --ai` is the opt-in model pass (off by default, init-time
only). With an LLM configured (`LLM_PROVIDER`/`LLM_BASE_URL`/
`LLM_MODEL`, the same settings the ask endpoint uses), the model may
propose `target_service` and `spec` for drafted clients from the
scan's evidence. Suggestions are validated before they land: the
target must be a drafted service id and the spec must be a spec the
scan found, otherwise the suggestion is dropped and listed for
review. Applied suggestions are noted in the report with the model
name, and the draft header says AI-drafted fields require review.
The indexer never calls a model; the graph is built from the
committed `axon.yaml` alone.

## Web UI (`web/`)

React + Vite on design tokens, primitives, and components copied from Arc
into `web/base/` and `web/components/` (dark-first, colour = meaning, theme
switch including Colour mode). Pages: API catalog (the landing page),
Services, Service detail, API detail, Ask, Function→APIs, PR impact,
and Onboard.

There is deliberately no whole-graph overview: a full service map does
not scale to monorepos, so exploration starts from the API catalog and
stays per-API. The API detail page renders a pan/zoom request-flow canvas with card nodes,
elbow connectors, animated call packets, focus dimming, and a right-hand
node inspector. Ask is a dedicated agent page modelled on Arc's: centred
composer, engine picker, Skills list, thinking trace, one-line-per-fact
answers, and citations that navigate into the catalog. Without a backend
the main build shows an honest API-unreachable state and no graph data.
Demo is a separate build (`vite --mode demo`, via `npm run dev:demo` /
`build:demo`) that swaps the `@client` data source for a fixture dataset;
demo code and data are not part of the main build at all. See
`web/README.md` for the frontend layer rules.

## MCP (`axon-mcp/`)

A separately packaged stdio adapter proxies `/api/v2` through five tools:
`axon_search`, `axon_services`, `axon_api_graph`, `axon_function_apis`, and
`axon_ask`. It reads the API URL and optional bearer token from
`~/.axon/config.json`; `axon-mcp configure` writes that file and registers
the server in Claude Code's `~/.claude.json`. See `axon-mcp/README.md` for
client configuration and caching behavior.

## Legacy code still on disk

The v1 graph/ops/history modules and the Maven/pnpm/TS/Java/tree-sitter
workers remain in the tree but are not imported by the app, CLI, or
`pyproject` scripts. They are kept only as reference for a follow-up
physical purge. The default pytest and CI gates cover the active v2/CLI
implementation; legacy integration suites still need Neo4j (and some need a
running API) and are available by explicit path or through the manual
legacy CI jobs. The Bazel worker package and its dedicated tests are
deleted, although some orphaned legacy scenario tests still reference it.
